更新记录

English · 项目首页

以下保留已记录的版本变化；公开发行与下载以 Releases 为准。

2.2.6 更新

  • 支持在导入正式译名表前，直接编辑 AI 候选译名。
  • 多文件翻译选择继续审查后，后续检查沿用该选择，避免重复询问。
  • 修复 EPUB 文件夹校对报告的一键应用与正文跳转。

2.2.5 更新

  • 修复 EPUB 页面初始化及多文件翻译启动问题，支持原文与项目输出保存在同一目录。

2.2.4 更新

  • 翻译进入最终审阅时，直接提供“继续／跳过”提示，不必再用自然语言说明下一步。
  • 单文件模式应用审阅意见时，自动将完整译文导入页面并应用修改，无需手动导入，与多文件模式保持一致。

2.2.3 更新

  • 文件夹校对应用后自动刷新审阅页面，保留人工修改和当前子文件。
  • 修复 Agent 对齐检查的状态反馈，正确显示并读取未通过项。

2.2.2 更新

  • 修复校对跳转未复用已导入译文的 HTML，以及重建页面缺少 EPUB 导出的问题。

2.2.1 更新

  • 优化项目路径解析，保持校对应用、正文跳转和导出绑定一致，支持项目移动后继续使用。

2.2.0 更新

  • 新增文字层 PDF 翻译：提取正文及公式、代码、图表等资产，整理并审计文档结构后生成审阅 HTML，再用译文和保留资产自动重排生成新 PDF。支持完整段落、跨页续段和段内公式调序，保留代码、公式及参考文献。详见 PDF 使用说明。
  • 新增官方后台 Agent API，复用项目准备、翻译、校对和资料整理流程，支持状态查询、停止、续跑和用户答复。
  • 改善大项目处理：大历史会话和候选译文在后台加载、校验与导入，支持进度和取消；优化会话恢复及分块缓存复用。
  • 改善编辑体验：生成后自动进入 HTML，优化已有页面打开、译文导入、保存和关窗流程，保留人工修改。
  • 减少英文标识和角色名触发的漏译、术语误报，支持主 Agent 对具体漏译误报进行确认。

2.1.9 更新

  • 修复 2.1.4 带来的单文件模式回归。

2.1.7–2.1.8 更新

  • 漏译检查排除正则实际匹配的保留内容，以及术语表中在同一行正确对应的源词与译词；其余正文仍需翻译。用户明确要求保留的词由 Agent 记录为正式的「源词 → 原词」，候选导入和 AI 审阅使用相同规则。译名匹配、术语冲突及恢复重扫也排除正则保留片段。

  • 审阅绑定失效后，由 Host 停止旧工人、核验草稿并自动续跑；保留未变化行的通过证据，修复停止时的批次结算错误。

2.1.6 更新

  • 已绑定的必需文件缺失时停止整个工作流，保留草稿并提示恢复路径；未绑定的译名表、角色表允许缺省。
  • 修复立即中止与项目关闭的收尾死锁。
  • 修复 Electron HTML 关闭与停止任务的路径绑定；保存失败会明确提示并保留修改。
  • 项目内设置、HTML 和恢复产物使用相对路径；复制整个项目后仍可读取父/子 Agent 历史、草稿和审阅记录。项目外绑定的原文或资料需一并带走并重新选择。

2.1.5 更新

  • 修复大文件翻译卡死：分块检查只扫描当前范围，全文终检在后台执行，保留全部结构要求、审阅与中断恢复。
  • 校对建议复用翻译的格式保留要求与机械检查，防止丢失控制符、标签和占位符。
  • 修复并发中断恢复：Host 在启动 Worker 前统一核查、交接已有译文、staging 与审阅记录；提交失败保留可恢复产物，不可重试的内部错误停止整个工作流。

2.1.4 更新

  • 整理参考资料可直接新建并绑定项目，在翻译前准备译名表和角色表；首页支持一键清空填写内容并恢复默认参数。

  • 资料整理先生成可修改、删除的草稿，核查后一次性提交正式译名表和角色表；中断或失败保留草稿。

  • 简便启动先核对参数与原文、试跑控制符保留规则，再使用 HTML 共用参数表和相同翻译提示词；需要人工介入时可先生成行对行 HTML。

  • 移除无效的分块开关，保留每块行数；文件夹 HTML 自动填入带大括号的文件顺序，保留已填写的选择。

  • 首页顶部可直接配置供应商和模型，无需先选择项目或打开 HTML；设置全局共用。

  • 首页新增内置 Agent 任务入口：确认参数后自动打开 HTML 并启动翻译或校对，也可直接整理项目资料。默认分块 500 行、子 Agent 上限 3；翻译前预扫并试跑保留规则。

  • HTML 新增角色表查看、编辑和删除；校对可自动应用意见到 HTML，TXT 仍手动保存。

  • 修复停止后旧任务或压缩仍继续启动的竞态。

2.1.3 更新

  • 修复 Grok 4.7 被误发 reasoning_effort=none 的请求：自动及旧“关闭”配置使用官方默认 high，没有已知思考档位的模型不发送 effort 参数。
  • HTML 术语面板分别显示正式译名表与 AI 候选，导入前可查看、搜索和删除候选，正式表也支持逐条删除。删除仅修改对应表，不自动修改译文或角色资料；旧 HTML 打开时会自动升级。
  • 内核升级到 0.99.1，并完成各方面适配，避免回归。

2.1.2 更新

  • 标准 Provider 的模型目录可从 Pi 上游自动刷新，并在网络不可用时使用本地缓存或随应用发布的目录。
  • 修复停放的译文复用流程恢复、校对术语候选重试和 Workflow 类型恢复中的状态不一致。
  • 500 行模型分页与结构化修复上限保持一致，并合并同一行重复的长度风险信号。

2.0.5 → 2.1.0 更新

  • 超大审阅页能打开了：不再被 80 MiB 卡死；建议跳到原文，实测从大约 4 秒降到 1–2 秒。
  • 大文件翻译、校对更稳，内存不再越跑越高，预扫描也不再卡住主窗口。
  • 主窗口能自适应；角色可以给同一人追加多条台词。
  • 打开 Agent 或发短问题，不会把审阅页拉回顶部。
  • 手机远程改成全屏工作区，Agent 放进工具抽屉。

2.0.1 – 2.0.5：工作流可靠性与 Provider

  • 校对与 EPUB 始终遵循页面手选的权威译文绑定；翻译完成后，未手选的页面会跟随正式 translated 产物，不再误读临时快照。
  • 新增 Grok (OAuth)、按模型适配的思考等级和长推理等待；授权过期时刷新并恢复当前工作，而不是中断整批任务。
  • 翻译复审耗尽后把精确失败行交回主 Agent，校对 findings 由 Host 按当前绑定行校正；已通过结果不会被后续空写入或失败项清空。
  • 术语长名覆盖短名，跨文件术语差异进入最终警告复核；关闭术语候选时不再构造、更新或校验候选资产。
  • 批量应用保留人工修改和 TXT 写入状态，恢复命令明确区分翻译与校对，减少跨工作流误恢复。
