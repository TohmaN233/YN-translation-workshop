# PDF translation

[中文](pdf.md)

Manual HTML generation, built-in AI tasks and the official Agent API accept horizontal text-layer PDFs. Choose auto or pdf; folder auto supports mixed TXT, EPUB and PDF. Originals stay read-only. Preparation and translation share the existing native Pi Session/Runtime without another translation engine or task queue.

1. Every PDF must complete mechanical extraction, a native Pi structure proposal, Host validation and an independent Pi audit before HTML generation. The current provider, model and reasoning settings are used to inspect source rows and propose paragraphs, reading order and table relationships. Only accepted structure becomes a UTF-8 projection and review HTML, with one row per logical unit.
2. Use existing glossary, character bible, preservation and translation/proofreading tools. Proofreading needs translated TXT aligned with these rows, rather than an independently typeset PDF.
3. Sync current translations and click **Export reflowed PDF**. Export prepares structured HTML and source mappings, then hidden Electron Chromium wraps and paginates automatically. No TeX installation, extra translation calls or original prose-box length limit is required.

AI_translation contains name.translated.html, name.translated.document.json and name.translated.pdf. HTML includes current text and embedded source images/native glyphs; JSON records logical rows, source pages and relationships. External inputs use distinct subdirectories. Subsequent exports read current review-HTML translations. TXT saving remains separate and manual.

## Preprocessing and preservation

Mechanical extraction retains visual source rows, coordinates, page numbers, native glyphs, images and paint ownership. Host builds a complete structure draft covering every source ID. The model must still read all source IDs, but restricted tools let it edit affected paragraphs, roles, reading order and table rows, columns and spans incrementally, without emitting the entire unchanged plan in one response. Explicit merges expand all source IDs of anchored existing paragraph owners and return the expanded IDs for inspection; ordinary partial patches never expand implicitly. Explicit splits name the source ID starting a new group; Host retains the original prefix role and full suffix tail, returning expanded groups for inspection. Submit merges and splits separately. Edits check revision, complete source ownership and conflicts; draft tools in one batch run sequentially. A compact acknowledgment accepts the current revision only after a successful check. No-op edits keep the revision. Repeating the same structure, normalized edit attempt and failure without structural progress stops preparation; changing only the reason cannot bypass this. Different edits or structural findings remain correctable. The model cannot rewrite source text, translate or guess TeX. Source-evidenced page continuations and inline display formulas can connect complete prose.

Mechanical code first consumes same-page paragraph groups, then connects evidenced cross-page continuations and display formulas. Captions retain their continuation rows; table-cell and read-only ownership boundaries remain distinct. Draft creation uses these complete logical units instead of splitting them into visual rows again. The model mainly revises remaining ambiguities. Original physical source rows and paint mappings remain separately retained.

Multiple anchors selecting the same owner within one explicit merge expand it once, in first-selection order, and return the anchor mapping and complete source IDs. Different merges or edit operations still cannot claim the same owner. Internal source order is never sorted automatically; reordering requires an explicit complete-group replacement.

Host hard checks enforce source identity and complete coverage, zero duplicate/foreign IDs, read-only content and renderable leaf/table/rule-frame ownership. Fonts, indentation, columns, PDF paragraph tags, page gaps, headings/captions and mechanical table candidates provide geometryFindings for proposal and independent audit; thresholds and guesses alone cannot reject different PDFs. A semantic table can be withdrawn into a source-rule panel with translatable prose. Declared cells still require exact source owners, integer columns/spans and valid bounds. The pre-HTML source-structure check is not proof of page appearance or final layout quality.

After applying the proposal, independent native Pi audits use packets containing complete paragraphs, table and figure dependencies, original source rows, current logical owners and neighboring evidence. Each packet starts with cleared context; a separate packet checks complete section and global reading order. Host fixes exact source, owner, boundary and relationship responsibilities. All current packets together must cover every source row, logical owner, START/END/adjacent reading edge and table/figure relation. Reading context does not pass another packet. Acceptance requires 100% source coverage, zero duplicate or foreign IDs, native-glyph/graphic/figure coverage of 1, unchanged protection and a passing semantic audit. These metrics establish preservation and ownership of extracted content; semantic acceptance remains a model judgment, not a guarantee for every PDF or translation.

Each packet submits structured checks through a restricted typed tool after every required record has been read. Only an unchanged packet with a positive typed submission and fully settled native lifecycle can be reused. A negative packet never implies that unlisted parts passed. Edits rebuild current packets and exact coverage; accepted evidence is persisted and revalidated with the layout. Additional read-only investigation remains available; reading other prepared owners binds additional current layout dependencies. Host validates the schema, known IDs and consistency between checks and issues. Ordinary final text is diagnostic only; it cannot authorize HTML or replace a submitted audit. Identical submissions are idempotent; a different second submission fails. Native completion, persistence and close must still settle after submission.

Proposal and independent audit finish before HTML or translation starts. A negative audit includes an executable source-only correction. Host validates complete owners, related findings, inspected evidence, structural change and native render ownership on a snapshot. Only successful native settlement commits the correction; changed packets then receive fresh independent audits without another full-document proposal. Stable source-ID buckets keep unrelated packet boundaries unchanged. An unrepresentable confirmed defect explicitly stops preparation. Formatting preferences, no-op edits, reasons and table names cannot count as repairs. Every input, finding, correction and output is retained; acceptance binds only the fully passing plan and audit. Missing configuration, exhausted structural progress, failed acceptance or Stop produces no new HTML.

Mechanical geometry distinguishes inline formulas from independent displays using same-line surrounding prose, native bounds and body-wrap evidence. Native glyphs remain read-only. Audit views expand the actual prose/native reading sequence so punctuation inside a formula is directly visible. This is extracted glyph text, not reconstructed TeX or replacement source prose.

A local correction can use explicit ordered steps when it needs both merging and splitting. Host validates each step on a private snapshot and commits the whole correction only after complete validation and native settlement. A later failure applies none of the earlier steps. A split assigns its kind to the suffix and retains the prefix role.

Inline code/math uses {{formula:pN:id}} and {{code:pN:id}}. Agents get original content as read-only context. Host checks identity, count and paragraph ownership. Markers may move within their paragraph for target syntax, but cannot be deleted, duplicated or moved across paragraphs. Marker-only prose remains unfinished. Export restores native glyphs in target order, including display formulas and fraction bars.

Read-only reference identity follows original physical source IDs; reference order and section gaps after reflow are independent-audit clues. Pure labels already owned by a figure group need not enter the caption; folios may be omitted from presentation while retaining source ownership. Code, independent formulas and References/Bibliography are Host-seeded and excluded from writable rows. All-protected chunks do not request a model. Proofreading, import, writes and export enforce exact equality, independent of editable regex rules; protected text does not trigger prose residue/terminology checks. Native tags, actual math fonts and explicit syntax identify protection; arbitrary unmarked formulas are not guaranteed detectable. Shared numeric/inline paints use precise character ownership; inseparable ownership rejects processing.

Every visible non-text path belongs to native code/math, proven table rules or a vector figure. Source graphics cannot silently disappear. Vector figures become source images; tables use source row/column relationships. Same-page panels retain their original group relationships and pure panel labels when ownership is safe. Translatable captions and descriptions remain separate; grouping cannot freeze prose. Unsafe text/graphic separation, overlapping raster graphics and competing owners fail explicitly. Image text stays unchanged; optional vision aids understanding without rewriting it.

Verified-source prescanning supplies row-scoped evidence for software/dataset names, defined acronyms, numbering, URL/DOI and table labels. Translation, review and residue detection share actual positions; explicit glossary targets win and surrounding prose remains checked. English names do not cause rejection solely through shared word counts. Parent confirmTranslationResidueSafe records reasons for exact-row false positives; source/candidate changes invalidate decisions without weakening structural protection.

Source tools expose lightweight page/figure indexes and request images only when needed. Cross-page units retain each fragment's source page. Text-only models can translate text; image requests explain when a vision model is needed.

## Layout, migration and diagnostics

Output uses A4 and bundled Noto Sans SC with selectable prose and automatic wrapping/pagination. Page count, text positions, typefaces and original page breaks change. Translation need not be shortened or squeezed to 6 pt. Images/native glyphs fit pages proportionally with complete content, rasterized at up to 2x and a 3000-pixel maximum long edge, rather than original vectors/selectable text. Inspect formulas, tables and reading order.

Font/image failures, changed bindings, invalid markers and cancellation report explicitly. A verified complete PDF replaces the prior output atomically. Source preparation and printing have separate logs. Same-output preparation/printing is serialized so concurrent windows cannot print another request's target. Cancellation awaits worker and hidden-window cleanup; failures remain visible.

Current layout is **v5/e15**, with structure-preparation prompt contract **v9**. Extractor revisions and prompt contracts use separate projection scopes; older acceptance records cannot be reused directly and their formal mappings are not overwritten. Visual source units and accepted paragraph mappings are retained separately. Older tasks must regenerate from the original and pass structure preparation. Prior projections, translations and sessions remain available; old row numbers cannot automatically authorize translation/review-evidence migration. Reuse needs verified source fragments, duplicate-prose inspection and complete marker checks.

Horizontal text-layer PDFs are supported without OCR. Scans, hidden OCR, text over full-page bitmaps, rotated/vertical text and text clipping masks fail explicitly. Complex columns may need manual preparation. Annotations/forms are not exported; original bookmarks are not copied.

Projections, page assets and hash layouts live under .translation-workshop/extracted-text. *.pdf-mechanical.json retains mechanical source units; *.pdf-draft-revision-*.json retains draft revisions; *.pdf-structure.json retains the accepted proposal and audit; *.pdf-proposal-model.json and *.pdf-audit-model.json retain native responses and inspection records. Each attempt also retains its own directory under *.pdf-preparation-attempts, so repeated runs preserve earlier diagnostics; events link their paths. *.pdf-segmentation.json records visual-row evidence; graphic-ownership-*.json records native graphic ownership. PDF events use .translation-workshop/pdf/events.jsonl; homepage events use .translation-workshop/html-generation/events.jsonl. Native Session JSONL records preparation stages and model identities.

Accepted projections reuse zero new model requests after background revalidation of the original PDF hash, mechanical source, proposal/audit, projection and asset pins. Missing or tampered evidence rejects reuse; layout reads and Host preflight share the acceptance boundary. Copy the whole project for relative bindings; transfer and reselect external PDFs separately.

Opening existing HTML does not rerun the structure model. Current and v10 batch indexes prepare the selected child only; other children wait until selected, while earlier formats retain necessary migration. Saved translations and revisions restore through a read-only operation before editing becomes available. Initial PDF preparation has separate progress and Stop controls. Model inspection defaults to text, source IDs, pages and actual protection; geometry or source pages are requested for uncertain spatial relationships instead of repeatedly sending the full layout and plan.

The intermediate structure draws on [BabelDOC](https://github.com/funstory-ai/BabelDOC), and continuous reading/region traceability on [EasyRead](https://github.com/Edwardxlai/easyread). YN uses native Pi to propose and audit structure while Host retains deterministic source identity and ownership. PDF.js extracts/renders originals; Electron Chromium typesets HTML and prints PDF.
