# PDF 翻译

[English](pdf.en.md)

首页生成 HTML、内置 AI 任务和官方 Agent API 都接受横排文字层 PDF。选择 auto 或 pdf；文件夹 auto 支持混合 TXT、EPUB、PDF。原 PDF 只读，准备与翻译复用同一个原生 Pi Session/Runtime，不另建翻译引擎或任务队列。

1. 每份 PDF 在生成 HTML 前必经机械提取、原生 Pi 结构提案、Host 校验与独立 Pi 审计。模型使用当前选择的供应商、模型及 reasoning 设置读取源行，提出段落、阅读顺序和表格关系；通过验收后才提交 UTF-8 投影及 HTML，每个逻辑单元一行。
2. 使用现有译名表、角色表、保留规则和翻译／校对流程。校对需与投影逐行对应的译文 TXT，不能用另一份重新排版的 PDF 对齐。
3. 同步当前译文，点击 **导出重排 PDF**。先生成结构化 HTML 源码及来源映射，再由隐藏的 Electron Chromium 自动换行、分页。无需安装 TeX，不额外调用翻译模型，不要求译文装进原正文文本框。

输出在项目 AI_translation 中：原名.translated.html、原名.translated.document.json 和原名.translated.pdf。HTML 包含当前译文、嵌入的源图片及原生字形；JSON 记录逻辑行、源页和结构关系。外部输入使用独立子目录。再次导出读取当前审阅 HTML 的译文；保存 TXT 仍是独立手动操作。

## 预处理与保留

机械提取保留视觉源行、坐标、页号、原生字形、图片与绘制归属，并由 Host 建立覆盖全部源 ID 的完整结构草稿。模型仍须读取全部源 ID，但只需通过受限工具增量修改有问题的段落、角色、阅读顺序及表格行列／跨列关系，无需在一次回答中重新枚举整份不变计划。显式 merges 锚点操作可展开现有段落 owner 的全部源 ID，再合并完整单元；返回展开后的 ID 供模型核对，不会隐式补齐普通 partial patch。显式 splits 只需给出新单元起始源 ID，自动保留原 owner 的前段角色及完整后段尾部，并返回展开分组供核对；合并和切分分步提交。修改检查修订号、完整源归属及冲突，同批草稿工具依次执行；检查通过后以简短确认接受当前 revision。无变化的修改不进版；重复同一结构、规范化修改尝试及失败原因而无结构进展时停止，仅改 reason 不能解除。不同修改尝试或结构错误仍可继续纠正。模型不能改写原文、翻译或猜测 TeX。有源文依据的跨页续段及句中展示公式可以连接正文。

初始草稿先由机械代码消费同页段落分组，再连接有依据的跨页续段及展示公式；图注续行随完整图注处理，表格单元和只读归属保留边界。草稿直接沿用这些完整逻辑单元，避免再次逐视觉行拆碎。模型主要修订余下歧义；原始物理源行和绘制映射始终独立保存。

同一次显式合并的多个锚点若选中同一 owner，只按首次选中顺序展开一次，并回报锚点对应关系和完整源 ID；不同合并或修改操作争用同一 owner 仍会拒绝。owner 内部源 ID 不自动排序，重排须显式替换完整分组。

Host 硬检查源身份与完整覆盖、零重复／外来 ID、只读内容及可渲染的叶子／表格／规则框归属。字体、缩进、分栏、PDF 段落标记、页间距离、标题／图注和机器表格候选只作为 geometryFindings 线索交给提案与独立审计，不能仅因阈值或猜测拒绝不同 PDF。语义表格可撤回为保留规则框的可译正文区域；声明的单元仍须满足源 owner、整数列／跨列及边界检查。HTML 前的源码结构检查不等于页面外观或最终排版质量保证。

提案应用后，独立原生 Pi 审计按完整段落、表格及图组依赖分成局部包，每包清空上下文，读取对应的原始源行、已组装逻辑单元和相邻证据；另一个包检查完整章节与全局阅读顺序。Host 固定每包的源 ID、逻辑单元及边界关系责任，所有当前包共同精确覆盖全部源行、逻辑单元、START／END／相邻关系和图表归属；上下文读取不能替其他包通过。每包通过受限 typed 工具提交结构化检查结果；Host 校验该包全部必需记录已读、字段与已知源 ID、检查项和问题一致性。输入完全未变、正提交且原生生命周期已收尾的包才可复用；负包不推断未列问题的部分通过。修订后重建当前包并核对全部精确覆盖，接受证据随布局保存，复用时重新核验。合法额外只读调查继续开放；读取其他已组装单元会绑定额外的当前排版依赖。普通最终文本只留诊断，不能授权 HTML 或覆盖已提交结果；相同提交幂等，不同的第二份提交明确失败。提交后仍须等待原生请求、持久化及关闭真实收尾。必须同时达到源覆盖 100%、重复及外来 ID 为 0、原生字形／图形／图像覆盖为 1、保护内容未变，并通过语义审计，才提交接受记录与正式布局。覆盖指标证明已提取源内容的保存与归属；语义审计仍是模型判断，不保证所有 PDF 的结构或翻译质量。

提案与独立审计都在 HTML 和翻译开始前完成；工具读取可能包含多轮模型交互。负审计须附可执行的源结构修订，Host 在副本上检查完整 owner、问题关联、已读依据、结构变化及原生可渲染归属；原生请求收尾成功后才提交修订，再清空上下文重审变化的包，不再让另一轮模型重读全篇并猜修法。完整依赖按稳定源 ID 窗口归包，局部修订不推移无关分组边界。不可表达的真实问题明确停止；排版偏好、无变化或仅改 reason／表格名称不能伪装修复。每轮输入、问题、修订和输出分别留档，最终接受记录只绑定全部通过的计划与审计。未配置模型、无法继续纠正、验收失败或 Stop 都不生成本次 HTML。

机械代码依据同一视觉行的左右正文、原生字框和正文续行几何，区分行内公式与独立展示公式，保持源字形只读。审计视图按实际顺序展开正文及原生节点文字，括号等位于公式节点内的字符直接可见；这只是源字形的提取文本，不是猜出的 TeX，也不写回源文。

需要先合并再切分的局部修订可提交显式 steps。Host 在私有副本上逐步核对修订和源归属，全部校验与原生收尾完成后才原子提交；后一步失败时前一步也不应用。切分的 kind 指定后段角色，前段角色保留。

段落内代码／公式用 {{formula:pN:id}}、{{code:pN:id}} 表示，模型得到原始内容的只读上下文。Host 检查身份、数量和所属段落，允许同段内随译文语序调序；不能删除、重复或跨段移动，只有标识没有正文仍算未完成。导出按译文顺序恢复字形，保留展示公式及其分数线等原生绘制。

参考文献只读身份依原始物理源 ID 保持，重排后的引用顺序及区段间隔作为独立审计线索；组图已拥有的纯标签无需合入图注，页脚可省略呈现但保留源归属。代码、独立公式及 References/Bibliography 由 Host 预填并排除出可写列表，纯保留分块不请求模型。校对、导入、写入、导出要求逐字一致，不作正文漏译或术语检测，不能清空正则解除。依据结构标记、实际数学字体及明确语法识别，不承诺识别任意未标记公式。共享数字／内联绘制按字符范围分离；不能确定归属时拒绝。

可见非文字路径必须归属于原生代码／公式、确证表格规则或矢量图，不能静默漏出。矢量图保留为源图像，确证表格以源行列关系重建。同页面板在可安全归属时保留原始组图关系及纯面板标签；可译图注／说明保持独立，不能为合组而冻结正文。不能安全分离正文／图形、图形叠加位图或竞争归属时明确拒绝。图内文字保留原样，模型按需看图理解，不自动改写图中文字。

后台预扫描核验过的源文，为软件／数据集名、定义缩写、编号、URL/DOI、表格标签提供行内保留依据。翻译、复核和漏译检查共享实际位置，显式译名表优先，周围正文仍检查。英文姓名不会仅因共同词数量拒绝。主 Agent 可通过 confirmTranslationResidueSafe 为具体行的漏译误报记录理由；原文或候选变化后失效，不能解除结构保护。

看图工具提供轻量源页和图表索引，只有需要视觉信息时读取图片；图片不自动加入每块。跨页逻辑单元保留每个源片段的实际页号。非视觉模型可翻译文字，看图请求会提示需要视觉模型。

## 排版、迁移及诊断

输出使用 A4 和内置 Noto Sans SC，正文为可选中文字，自动换行、分页。页数、正文位置、原字体样式和分页会改变；不要求缩短译文或缩成 6 pt。图像按比例适配页面，保留完整内容；原生字形／图片以最高 2 倍、最长边 3000 像素图像保存，不能当作原矢量或可选文字。导出后检查公式、表格和阅读顺序。

字体／图片加载失败、绑定变化、非法标识或取消会明确报告，完整 PDF 验证并原子提交前不替换上次 PDF。源码准备与打印分别记日志；同一输出的准备和打印串行执行，避免多个窗口串用译文。取消等待 worker 解码及隐藏窗口正常收尾，清理失败可见。

当前布局为 **v5/e15**，结构准备提示契约为 **v9**。不同提取修订及提示契约使用独立投影作用域；旧契约接受记录不能直接复用，也不会覆盖旧正式映射。视觉源单元与接受后的段落映射分别保存；旧任务须从原 PDF 重新生成并通过结构准备。旧投影、译文、会话保留，不能按旧行号自动搬迁译文或复核证据。复用旧译文需核对源片段、重复句和全部保留标识后再导入。

支持横排文字层 PDF，不提供 OCR。扫描页、隐藏 OCR、整页位图叠字、旋转／竖排和文字剪裁蒙版会报错。复杂多栏阅读顺序仍可能需人工整理。注释、交互表单不导出，原书签不复制。

投影、源页资产及 hash 布局在 .translation-workshop/extracted-text；*.pdf-mechanical.json 保存机械源单元，*.pdf-draft-revision-*.json 保存结构草稿修订，*.pdf-structure.json 保存接受的提案与审计，*.pdf-proposal-model.json／*.pdf-audit-model.json 保存原生模型结果与读取记录。每次尝试另存于 *.pdf-preparation-attempts 下的独立目录，重复运行不会覆盖之前的诊断，事件记录包含对应路径。*.pdf-segmentation.json 记录视觉行依据，graphic-ownership-*.json 记录原生图形归属。PDF 事件在 .translation-workshop/pdf/events.jsonl，首页生成事件在 .translation-workshop/html-generation/events.jsonl；原生 Session JSONL 记录结构准备阶段及模型身份。

已有接受记录的投影在后台重新核验原 PDF hash、机械源、提案／审计、投影和资产绑定后复用，不新增模型请求。证据缺失或被篡改明确拒绝，布局读取和 Host 预检使用同一验收边界。复制整个项目恢复相对绑定，外部 PDF 须一并带走并重新选择。

打开已有 HTML 不重新运行结构模型。当前批量索引及 v10 索引只准备所选子页，其余页面在切换时处理；更早的格式保留必要迁移。页面先只读恢复已保存的译文与修订，再允许编辑，不用一次空写入换取读取。首次导入 PDF 的结构准备单独显示进度并支持 Stop；模型默认读取文字、源 ID、页号和实际保护依据，空间关系有疑义时按需读取几何或源页，避免反复发送完整布局和计划。

参考 [BabelDOC](https://github.com/funstory-ai/BabelDOC) 的中间结构思路及 [EasyRead](https://github.com/Edwardxlai/easyread) 的连续阅读和区域追溯设计。YN 用原生 Pi 提议及审计结构，Host 保持确定性源文身份与归属。PDF.js 提取／原生渲染，Electron Chromium 排版 HTML 并打印 PDF。
