# PDF 翻译

[English](pdf.en.md)

首页普通生成 HTML、内置 AI 翻译和官方 Agent API 都接受 PDF 原文。选择 `auto` 或 `pdf`；文件夹的 `auto` 支持混合 TXT、EPUB、PDF。默认分块和子 Agent 数量沿用现有设置。

1. 选择带文字层、可选中文字的 PDF。提取时将同页正文的视觉换行、首行缩进和列表悬挂缩进合并为完整段落，每段对应 UTF-8 原文及 HTML 的一行，原 PDF 保持只读。
2. 使用现有译名表、角色表、保留规则及翻译/校对流程。校对需选择与这些行对应的译文 TXT，不能用重新排版的另一份 PDF 作为对齐译文。
3. 在 HTML 中同步译文，按需编辑或应用校对意见，点击 **导出 PDF**。导出读取当前 HTML 的译文，保存到项目 `AI_translation` 中的 `原名.translated.pdf`；外部原文件使用独立子目录，避免重名覆盖。保存 TXT 仍是独立的手动操作。

视觉模型通过源文行得到轻量页面/图表索引。只有内容提到图表或需要视觉信息时，Agent 才调用看图工具；图片不会自动加入每个分块的上下文。图号支持跨页定位，矢量图和表格可通过对应页面查看。非视觉模型仍能翻译文字；需要看图时会提示选择视觉模型。

翻译前，后台在核验过的原文上预扫描有声明依据的软件包名、缩写、编号、URL/DOI 和表格字母类标签。翻译与复核收到同一份行内保留项，漏译检查只排除正确保留的对应内容，周围正文继续检查；显式译名表优先。扫描复用 PDF 绑定核验结果，不额外调用模型，不要求旧 HTML 重新生成。未获得明确源文依据的专名仍需通过译名表指定。

段落内的代码和公式显示为不可编辑的保留标识；Agent 同时收到原始内容的只读参考，只翻译周围正文。Host 检查标识的身份、数量和顺序，不能删改、重复或跨段移动，只有标识而没有正文仍算未完成。导出按原来的各行及公式前后可写区域排版，测量实际字形边界，不让译文覆盖原公式。段落目前按页组织；跨页续段通过相邻行提供上下文，不能补写另一页的内容。新段落投影使用 v3 布局，旧 PDF 任务需要从原文件重新生成 HTML，旧文件和会话会保留；旧行号对应的译文和审核证据不会直接搬到新段落。

代码和数学公式不可翻译。提取时依据 PDF 的 Code/Formula 结构标记、数学字体及明确的代码／公式语法识别保护块；HTML 显示原文并锁定对应译文行。Host 在模型翻译前把原始代码与公式填入工作稿，可写列表只包含正文，保留行作为只读上下文；回写时沿用原始行号，不让模型抄写或修复这些内容。纯保留内容的分块无需翻译模型请求。Host 在校对建议、候选导入和导出时仍要求这些行逐字一致，不能由清空自定义正则解除。注释、缩进、公式符号也属于保护内容，不作漏译或译名冲突检查；周围正文照常翻译。导出保留原始字形的页面图像，不用正文字体重画公式和代码。

数学字体使用 PDF 的实际字体名识别；分离的上下标、括号和罗马字体运算符按公式片段保留，不把单字符变量当成正文单词。绘制绑定使用与 PDF.js 提取一致的 Unicode 规范化，避免 `µ`／`μ` 等差异导致绑定失败。表格数字即使与相邻单元格共用绘制指令，也按完整字形的字符范围单独提取；不能唯一分离的字形仍会报错。

带有 Python 标签或连续行号和明确代码语法的代码面板也可识别，包括续页和分色文字；代码中的原有语法错误不会导致它变成待译正文。图像范围按实际裁剪区域计算。设计工具生成的“文字轮廓＋可复制文字层”只在相邻绘制组和坐标能唯一对应时处理：移除正文轮廓，保留代码／公式轮廓，不能确认归属时拒绝提取。

普通 PDF 不一定提供代码／公式的语义信息，因此不能保证识别任意未标记内容。检测到与正文混在同一不可分离文本绘制中的公式／代码会明确拒绝提取，需先给 PDF 加标记或分离内容。旧版未带此保护信息的 PDF 投影不能继续启动或提交，需从原 PDF 重新生成 HTML；旧投影和译文保留，不自动覆盖。

PDF 原生的段落、列表和表格单元格标记用于区分处理边界。未标记且严格对齐的分栏／表格不能仅凭坐标可靠区分：这类并排区域保持独立行，HTML 和模型源文参考会提示不能补写相邻内容，诊断记录相关行数；复杂分栏可能需要先整理原 PDF。窄栏正文不会因宽度不足而被拆成碎句。

参考文献（References/Bibliography）保留原文，由 Host 预填并从模型可写列表中排除；导出保留原始页面字形。现有 v3/e4 投影及 HTML 会重新绑定这一保护，不需要再次提取。疑似未译误报可由主 Agent 逐行说明理由并用 `confirmTranslationResidueSafe` 确认；TXT、EPUB、PDF 共用该能力，原文或候选变化后确认失效，不能解除公式、代码、行数或占位符保护。

## 版面与当前限制

导出保留页数、页尺寸、文本块位置、文字颜色、图片和表格线条。正文重新绘制为可选中文字，使用内置 Noto Sans SC 字体，原字体、粗斜体样式和精确字距不保证一致。非文字图形和保护的代码／公式以最高 2 倍、最长边 3000 像素的页面背景保存，因此这部分不再是可选文字或原矢量对象；内置字体完整嵌入，会增加数 MB 的文件大小。

正文按文本框和相邻行的实际空间换行、缩小，最低为 6 pt（原文字更小时保持原大小上限）。未改动的数字使用独立的原始字形资产，按实际墨迹范围保存，避免字体替换或字形外伸被裁。若仍放不下，会提示页号和行号，保持上次导出文件；请缩短对应译文后重试，不会裁切或丢掉文字。建议导出后检查分页、表格和公式。

第一版主要支持横排文字层 PDF，不提供 OCR；识别到扫描页、隐藏 OCR、整页位图上叠字、旋转/竖排文字或文字剪裁蒙版时会明确报错。PDF 阅读顺序沿用文件中的文字顺序，复杂多栏文档可能需先整理原文。注释、交互表单和书签不导出。图片内部文字随原图保留；看图用于帮助理解，不会自动改写图中文字。

生成时按钮旁立即显示状态和 PDF 页数进度，失败原因也显示在这里。页面 PNG 使用快速无损编码，保留原分辨率和像素。原文件和提取器未变时复用已有投影，在一次后台校验中核对全部页面及数字字形资产，不重复渲染。

取消会通知 PDF worker 停止，并等待当前解码和资源释放完成后返回；不会强制终止解压线程。清理失败会同时保留取消原因、具体错误和文件路径，写入诊断日志。

文本投影、页面资产及带 hash 的布局映射保存在 `.translation-workshop/extracted-text`；PDF 诊断在 `.translation-workshop/pdf/events.jsonl`，首页生成请求记录在 `.translation-workshop/html-generation/events.jsonl`。布局同时固定提取器 revision，新生成任务不会复用旧算法资产；已绑定旧提取器的任务会明确要求从原 PDF 重新生成，保留旧投影和译文。整个项目复制后，项目内绑定按新根目录恢复；原 PDF 在项目外时应一并带走并重新选择。运行期间不要移动或删除已绑定资产。

实现借鉴 [BabelDOC](https://github.com/funstory-ai/BabelDOC) 保留中间版面信息的思路，使用 PDF.js 提取/渲染和 pdf-lib 排版，翻译仍由 YN 原生 Pi 工作流执行。
