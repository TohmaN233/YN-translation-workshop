PDF translation

中文

Before translation, the background binding check scans verified source text for declared software and dataset names, defined acronyms, numbering labels, URL/DOI identifiers and letter-class table labels. Translation and review receive the same row-scoped preservation evidence. Residue checks exclude correctly retained source positions while still checking surrounding prose; explicit glossary targets take precedence. Scattered English names in translated prose no longer cause rejection merely through a shared word count; retained English prose and phrases are still checked. This reuses the PDF binding check without extra model requests or regenerating existing HTML. The parent Agent can inspect and confirm remaining exact-row false positives.

Manual HTML generation, built-in AI tasks and the official Agent API accept PDF sources. Choose auto or pdf; folder auto accepts mixed TXT, EPUB and PDF inputs. Existing chunk and agent settings apply.

  1. Select a PDF with selectable text. Extraction creates a read-only UTF-8 projection: one complete page-local prose paragraph per HTML row, combining visual wraps, first-line indentation and hanging list indentation. The original PDF stays unchanged.
  2. Use the existing glossary, character bible, preservation rules and translation/proofreading workflow. Proofreading requires the aligned translated TXT, rather than an independently typeset PDF.
  3. Sync translations in HTML, edit or apply proofreading suggestions, then click Export PDF. Current HTML text is saved under the project's AI_translation as name.translated.pdf; external inputs use separate subdirectories to avoid filename collisions. TXT saving remains a separate manual action.

Source reads expose a lightweight page/figure index. A vision model requests an image only when the passage mentions a figure/table or needs visual evidence; images are not attached to every chunk. Figure labels can resolve across pages. Page references cover vector diagrams and tables. Text-only models can translate text and receive an explicit error if they request an image.

Inline code/formulas appear as immutable references within complete paragraphs. Agents receive their original text as read-only context and translate surrounding prose. The Host checks marker identity, count and paragraph ownership; markers may be reordered within their paragraph to fit translated syntax, but cannot be deleted, duplicated or moved between paragraphs. Marker-only paragraphs remain unfinished. Export places each original native glyph in translated marker order while retaining the page background, and reports layout overflow explicitly. Paragraphs remain page-local; adjacent rows provide cross-page context without completing another page. New paragraph projections use layout v3: regenerate old PDF HTML from the original, retaining old files/sessions; old row-aligned translations and review evidence are not transferred by row number.

Code and mathematical formulas are not translatable. Extraction identifies protected blocks from PDF Code/Formula structure tags, mathematical fonts and explicit code/equation syntax. HTML displays the original and locks the matching target rows. Before model translation, the Host fills the working draft with original code/formulas. Writable lists contain only prose; protected rows remain read-only context and retain their physical line numbers during merging. Models never copy or repair them. All-protected chunks require no translation model requests. Proofreading fixes, imports and export still require exact equality; clearing editable regex rules cannot disable this protection. Comments, indentation and mathematical symbols are protected too; they do not trigger untranslated-language or glossary-conflict checks. Surrounding prose is translated normally. Export keeps original glyphs in the page image rather than redrawing code or formulas with the prose font.

Math detection uses actual PDF font names and preserves separated subscripts, delimiters and Roman-font operators within formula fragments. Paint binding uses the same Unicode normalization as PDF.js extraction, including µ/μ. Numeric table cells sharing a text paint with adjacent cells are isolated by complete glyph character ranges; ambiguous or indivisible glyph ownership still reports an error.

Code panels with a Python label or consecutive line numbers and concrete code syntax are also identified, including continued pages and syntax coloring. Existing syntax errors do not turn code into translatable prose. Image bounds respect clipping. Design-tool PDFs combining outlined text with a selectable text layer are supported only when adjacent drawing groups and transforms establish unique ownership: prose outlines are removed while code/formula outlines remain. Ambiguous ownership rejects extraction.

PDFs may lack semantic code/math information, so arbitrary unmarked content cannot be guaranteed detectable. Detected code/formulas sharing inseparable text paints with prose reject extraction explicitly; tag or separate them first. Old PDF projections without this protection cannot start or commit. Regenerate HTML from the original PDF; old projections and translations are retained rather than overwritten.

Native paragraph, list and table-cell tags establish boundaries. Untagged, strictly aligned columns and tables can have identical geometry: ambiguous parallel areas remain independent rows. HTML and model references warn against completing neighboring content, and extraction diagnostics record the count. Complex columns may need source preparation. Narrow prose columns have no minimum-width requirement for paragraph merging.

References/Bibliography sections remain in their original language, are seeded by the Host and excluded from model-writable rows. Export retains their original page glyphs. Existing v3/e4 projections and HTML gain this binding without re-extraction. The parent can use confirmTranslationResidueSafe with exact rows and reasons for untranslated false positives in TXT, EPUB or PDF. Changed source/candidates invalidate the decision; code, formulas, line structure and placeholders remain enforced.

Layout and current limits

Export retains page count and sizes, text positions and colors, images and table lines. Target prose remains selectable and uses bundled Noto Sans SC. Original prose typefaces, bold/italic styling and exact spacing are not preserved. Non-text graphics and protected code/formulas become page backgrounds rendered at up to 2x, with a maximum 3000-pixel long edge, rather than selectable text or original vectors. The complete embedded font adds several MB to the output.

Text fits within its box and the space before the next overlapping row, down to 6 pt (or its smaller original size). Unchanged numeric labels use isolated native glyph assets with actual ink bounds, preserving overhang and avoiding unrelated neighboring text. Overflow reports the page and row, leaves the previous export intact and requires shortening that translation; it never clips or drops text. Check pagination, tables and formulas after exporting.

This first version targets horizontal text-layer PDFs and does not include OCR. Detected scans, hidden OCR, text overlapping full-page raster images, vertical/rotated text and text clipping masks report explicit errors. Reading order follows the PDF text stream; complex columns may need source preparation. Annotations, interactive forms and bookmarks are not exported. Text inside images remains unchanged; visual tools aid interpretation rather than rewriting image text.

Generation immediately shows status and PDF page progress beside the button, including failure details. Fast lossless PNG encoding preserves the original resolution and pixels. If the source and extractor are unchanged, existing projections are reused after one background verification checks all page and numeric glyph assets; pages are not rendered again.

Cancellation asks the PDF worker to stop and waits for current decoding and resource cleanup before returning, without forcibly terminating the decoder thread. Cleanup failures retain the cancellation reason, specific error and file path in diagnostics.

Text, page assets and hash-bound layouts are stored under .translation-workshop/extracted-text; PDF diagnostics go to .translation-workshop/pdf/events.jsonl, and homepage generation requests to .translation-workshop/html-generation/events.jsonl. Extraction identity includes an extractor revision. New tasks re-extract after algorithm changes; existing obsolete bindings explicitly request regeneration from the original PDF and retain prior text and translations. Copy the whole project to retain relative internal bindings. External PDFs must also be transferred and selected again. Do not move or delete bound assets during a run.

The layout intermediate follows ideas from BabelDOC. PDF.js handles extraction/rendering and pdf-lib handles output; YN's native Pi workflow still performs translation.
