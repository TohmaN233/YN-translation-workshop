PDF 翻译：提取资产、重建 HTML、生成 PDF

English

YN 从原 PDF 提取正文、公式／代码字形、图片和图表等资产，整理成完整的逻辑结构，再用译文与保留的资产重建 HTML，自动排版成新的 PDF。原 PDF 保持只读；新文档的字体、分栏、页数和分页可以改变。

使用流程

  1. 选择原 PDF。 首页生成 HTML、内置 AI 任务和官方 Agent API 都支持横排文字层 PDF；选择 auto 或 pdf，文件夹 auto 可混合 TXT、EPUB 和 PDF。
  2. 提取资产并整理结构。 机械代码提取正文、源页、坐标、原生字形和图像映射，把视觉断行组织为逻辑段落，并连接有源文依据的跨页续段。当前配置的 Pi 模型只修订剩余的段落、阅读顺序或表格关系歧义，并进行独立结构审计；不会改写源文或猜测 TeX。程序检查源内容覆盖、重复及资产归属。通过后才生成工作文本和审阅 HTML。首次准备显示进度，可 Stop；失败或停止不生成本次 HTML。
  3. 在审阅 HTML 翻译和编辑。 一个逻辑单元对应一行工作文本，沿用译名表、角色表、保留规则及翻译／校对流程。校对需要与该投影逐行对应的译文 TXT。已有 HTML 打开时恢复保存的译文后即可编辑，不重新运行结构模型；生成完成会自动进入页面。
  4. 导出重排 PDF。 同步当前译文，点击 导出重排 PDF。导出将当前正文译文与源资产组装为结构化 HTML 源码及来源映射，再由隐藏的 Electron Chromium 自动换行、分页。无需安装 TeX，不新增翻译模型请求，也不要求译文装进原正文文本框。

哪些内容会翻译，哪些会保留

内容处理方式
正文、标题和可分离的图注翻译后在新 HTML 中自然排版
代码、公式和参考文献保留原始字形资产，由程序预填并保护
图片、矢量图和图表的图像部分保留源图像；图内文字不自动翻译
可以确认行列关系的表格按接受的结构重建，正文单元可译，保护单元保持原样

段落内代码／公式使用 {{formula:pN:id}}、{{code:pN:id}} 标识。允许在所属段落内随译文语序调序，但不能删除、重复或跨段移动；导出按标识恢复对应的原始字形。图片仅在内容需要时供当前视觉模型查看，不自动附加到每个翻译块。

输出与再次导出

项目的 AI_translation 中保存 原名.translated.html、原名.translated.document.json 和 原名.translated.pdf。HTML 包含当前译文及嵌入的源资产；JSON 记录逻辑行、源页和结构关系；PDF 是重新排版的成品。外部输入使用独立子目录。

再次导出读取当前审阅 HTML 的译文。保存 TXT 仍是独立手动操作。字体、图片或来源绑定失败会明确报告，完整 PDF 验证并原子提交前不替换上次输出。

支持范围与迁移

支持横排文字层 PDF，不提供 OCR。扫描件、隐藏 OCR、整页位图叠字、旋转／竖排、文字剪裁蒙版及不能安全分离或归属的内容会报错。复杂多栏仍可能需要整理阅读顺序；可在 HTML 中查看已接受的正文顺序、公式和图表后导出。注释、交互表单不导出，原书签不复制。

输出使用 A4 和内置 Noto Sans SC，正文为可选中文字；图像按比例适配页面。原生字形／图像以位图资产保留，最高 2 倍、最长边 3000 像素。

当前布局 v5/e15、结构准备提示契约 v9。已接受的投影在核验原 PDF、结构证据及资产绑定后复用，不新增结构模型请求。段落映射改变时，旧译文和复核证据不会按旧行号自动迁移；旧文件与会话保留，复用译文须核对来源与保留标识。

诊断与实现参考

工作文本、布局和源资产位于 .translation-workshop/extracted-text；机械提取、结构草稿、提案和审计结果分别留档，每次尝试保留独立诊断。PDF 事件记录在 .translation-workshop/pdf/events.jsonl，HTML 生成事件在 .translation-workshop/html-generation/events.jsonl。图片失败日志包含源节点、页码、逻辑行和公式标识。

PDF.js 负责提取与原生渲染，现有 Pi Runtime 负责结构修订及审计，Electron Chromium 将 HTML 排版为 PDF。参考 BabelDOC 的中间结构及 EasyRead 的连续阅读思路；验证依据见 质量检查。
