YN 质量与可靠性说明

English · 首页 · 使用实例

本页对应 2.2.0，区分程序可检查的结构约束、AI 语义审阅和用户实际翻译项目。它不是不同翻译工具的排名，也不把测试通过等同于译文语义正确。

当前验收范围

2026-10-13，本地 Windows x64、Node.js 24.14.1 的完整 npm test 通过 223 个测试文件；隐藏 Electron 39.8.10 / Node.js 22.22.1 下验证了 PDF 预扫描、翻译、修复与独立复核。版本和依赖以 package.json 与 锁文件 为准。

这些是本地验收，不是公开 CI 状态。原生 Pi 流程回归中的模型响应使用可控测试 Provider，验证范围、写入和恢复契约；这不构成真实模型的翻译质量评测。测试总数是该次验收快照，不是长期徽章。

如何复现

开发环境使用 Node.js 22.19 或更新版，安装仓库锁定依赖后：

npm ci
npm test

复现单个 PDF 冷恢复测试：

node --experimental-strip-types tests/pdf-protected-recovery.test.mjs

真实桌面与发布包的检查入口和隐藏 Windows 验收限制见 开发与验证。耗时、内存、Provider 重试与缓存命中会随模型、文本、机器和网络改变，不能从固定提示词或 500 行分块直接推导普遍费用优势。

能发现与仍会遗漏的问题

机械校验可拒绝缺行、损坏控制符、越权写入及不匹配证据。独立 AI 复审关注风险行和稳定样本；逐片精审校对覆盖负责范围，Monte Carlo 是抽样。模型可能漏掉误译、代词、口吻与逻辑问题；没有统一公开盲评，本页不提供语义准确率。

错误不应被当成成功。绑定的必需文件丢失、不可重试的内部故障或无进展修复会停止，保留草稿与诊断。代码、公式的识别受 PDF 信息和绘制结构限制；无法安全区分时明确拒绝，见 PDF 限制。
